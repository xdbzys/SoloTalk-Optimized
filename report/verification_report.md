### 逐场景明细

**1. ① 全优作答（照原文朗读 + 标准答案 + 完整复述）**

- 应有结果：卷面接近 60，折算 20，A 档
- 原算法：Part A 20.00 / Part B 12.80 / Part C 20.23，合计 **53.03**；无折算、无档次
- 优化版：Part A 18.00（语音语调 10.00 + 语速与内容 8.00）/ Part B 16.00 / Part C 23.06（内容 12.00 + 语言 3.40 + 流利 4.66 + 语音 3.00），合计 **57.06/60** → **19/20**，A 档
- 判定：✅ 接近满分且给出折算

**2. ② 全程未作答 / 空录音**

- 应有结果：卷面 0，折算 0
- 原算法：Part A 0.00 / Part B 8.00 / Part C 0.00，合计 **8.00**；无折算、无档次
- 优化版：Part A 0.00（语音语调 0.00 + 语速与内容 0.00）/ Part B 0.00 / Part C 0.00（内容 0.00 + 语言 0.00 + 流利 0.00 + 语音 0.00），合计 **0.00/60** → **0/20**，C 档
- 判定：✅ 0 分（原算法全空仍得 8.00 分）

**3. ③ 语义完全无关、但句子通顺的文本（原 BGE 映射会虚高）**

- 应有结果：Part B 信息维度、Part C 内容维度必须归零；语言/流利维度可得分是官方「四维独立给分」规则，非缺陷

## 三、折算规则（四舍五入，非银行家舍入）

| 卷面分 | 应得折算分 | 引擎输出 | 结果 |
|---:|---:|---:|---|
| 0 | 0 | 0 | ✅ |
| 1.4 | 0 | 0 | ✅ |
| 1.5 | 1 | 1 | ✅ |
| 4.4 | 1 | 1 | ✅ |
| 4.5 | 2 | 2 | ✅ |
| 30 | 10 | 10 | ✅ |
| 58.4 | 19 | 19 | ✅ |
| 58.5 | 20 | 20 | ✅ |
| 60 | 20 | 20 | ✅ |

> Python 内建 `round(1.5)` = 2（银行家舍入），官方要求 1.5 → 2、2.5 → 3，因此必须用 `floor(x + 0.5)`，引擎已按此实现。

## 四、原算法三大缺陷的量化证据

1. **Part A 负分**：`wer = 30.00`（未钳制），原 `accuracy = -29.00` → 原得分 `-580.0 / 20`（负分）；优化版同场景 **0.60 / 20**。
2. **Part B/C 系统性虚高**：原 `(cos+1)/2` 映射让语义无关文本稳定得到 **0.500** 相似度 → 单题白拿 `1.00/2` 分；同一输入优化版得 **0.00/2**（语言 0.00 + 信息 0.00）。这正是原 README 自述「B 偏高」的根因。
3. **Part C 单维度失真**：原实现把 24 分全部乘在「要点相似度」上，语言/流利/语音三维完全不计分；优化版拆为 **内容 12.0 + 语言 3.4 + 流利 4.7 + 语音 3.0 = 23.1/24**，与官方四维档次表一致。

## 五、结论

- 优化版在 10 个场景中全部符合官方评分档次预期；原算法在场景 ②③⑥ 明显虚高（**场景 ② 全程未作答仍得 8 分**，是 `(cos+1)/2` 基线偏差最直接的证据）、场景 ④ 产生负分、场景 ①⑤⑦⑨ 因单维度而无法体现档次差异。
- **关于场景 ③ 的总分**：官方 Part C 明确规定「内容 / 语言 / 流利 / 语音」四维独立给分，因此「用通顺英语流利地讲了一段完全无关的内容」在语言、流利、语音三维仍会得分（约 12/24 中的一部分）；这不等于评分不准，准确的度量是**信息维度与内容维度是否归零**（本场景均已归零）。原算法的总分低只是因为它把所有维度都压成了一个相似度，属于「错得恰好不明显」。
- 新增 60→20 折算与 A/B/C 档次，输出与广东省教育考试院公布口径一致。
- 全程零模型依赖，为后续「内存减小」腾出最大空间（详见 `docs/03_内存与体积优化报告.md`）。

### 已知局限（诚实说明）

- 离线模式下「语音语调」「发音」只能以词级对齐结果作弱代理，引擎已保守封顶（Part C 语音 ≤2 分）并标注来源；要真正对齐官方机考评分，需按 `docs/02_集成指南.md` 接入在线音素级发音评测。
- Part C 若作答内容完全跑题但语言流利，语言/流利/语音三维仍会给出部分分数（这与官方「四维独立给分」的规则一致，非 bug）。
